# Implementation Plan: Tool Installation

**Branch**: `002-tool-install` | **Date**: 2026-02-14 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `/specs/002-tool-install/spec.md`

## Summary

Implement a declarative, YAML-configured tool dependency installation system for Mage projects. The system uses Kubernetes API Machinery for versioned configuration (`.tools.yaml`), supports 6 install types (go, gem, npx, cargo, uvx, download), multi-source fallback with retry, parallel installation across ecosystems, update-to-latest across all registries, checksum verification for downloads, and a tool runner helper with secrets redaction and output capture. All implemented as importable Go library packages following the mage-common constitution.

## Technical Context

**Language/Version**: Go 1.25.4
**Primary Dependencies**:
- `k8s.io/apimachinery v0.35.x` — TypeMeta, scheme/codec, YAML serializer, ExponentialBackoff
- `hashicorp/go-version` — semver comparison (promote from indirect)
- stdlib: `archive/tar`, `compress/gzip`, `archive/zip`, `crypto/sha256`, `net/http`, `text/template`, `os/exec`
**Storage**: Filesystem — `.tools.yaml` config, `<tools-dir>/<GOOS>/<GOARCH>/` binaries
**Testing**: `go test`, table-driven, `t.Parallel()`, mock interfaces for HTTP/exec/filesystem
**Target Platform**: linux/amd64, darwin/arm64 (minimum); any GOOS/GOARCH with Go support
**Project Type**: Go library (importable packages)
**Performance Goals**: SC-001 (2 min cold install), SC-002 (5s warm/idempotent), SC-003 (80% CI speedup)
**Constraints**: No CGO for tool builds, idempotent installs, K8s API Machinery conventions, kube-api-linter
**Scale/Scope**: Typical project has 5-20 tools; parallelism across types, sequential within type
